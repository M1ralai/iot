Üç Katmanlı Yalın Sistem Mimarisi

Sistemin omurgası tek yönlü sensör akışı ve çift yönlü pompa kontrolü üzerine kuruludur. Tüm bileşenler aynı çalışma masasında 5V USB güç kaynaklarıyla güvenle çalıştırılabilir.

Donanım ve Saha Katmanı: Saksıdaki toprak nemini okuyan Düğüm 1 (kapasitif nem sensörü + ESP32), doğrudan Wi-Fi ağına bağlı değildir. Veriyi düşük gecikmeli ve kurulumu kolay ESP-NOW protokolüyle Düğüm 2'ye (Röle/Tekrarlayıcı ESP32) gönderir. Düğüm 2 paketi tekrar önleme filtresinden geçirip Düğüm 3'e (Ağ Geçidi ESP32) aktarır. Sulama pompasını süren 5V röle modülü, kablo karmaşasını azaltmak için doğrudan Düğüm 1 veya Düğüm 3 üzerine bağlanabilir.

Sunucu ve Veri Katmanı: Ağ geçidi ESP32, yerel Wi-Fi üzerinden bilgisayarda çalışan Python FastAPI (veya Node.js Express) sunucusuna basit bir JSON POST /api/telemetry isteği atar. Sunucu veriyi tek dosyalık SQLite veritabanına yazar, saatte bir ücretsiz ve anahtarsız Open-Meteo API üzerinden yerel yağış olasılığını çeker ve yanıt gövdesinde ({"pump": true, "duration_sec": 15}) sulama komutunu geri döner. Bu yöntem ayrı bir MQTT broker kurma zorunluluğunu da ortadan kaldırır.

Web Arayüzü: Tek sayfalık bir React veya yalın HTML/CSS/JS paneli; anlık toprak nemini, son 24 saatlik grafiği, düğümler arası atlama yolunu (Düğüm 1 → Düğüm 2 → Ağ Geçidi), Leaflet haritasındaki parsel işaretçisini ve Manuel Başlat / Durdur düğmelerini gösterir.

İki Temel Algoritma: Çok Atlamalı İletim ve Güvenli Sulama Kararı

Ödevin mühendislik ağırlığını taşıyan iki algoritma vardır: paketlerin düğümler arasında sonsuz döngüye girmeden aktarılması ve pompanın sensör arızasında veya yağmurlu havada hatalı çalışmaması. Aşağıdaki sözde kodlar (pseudocode) doğrudan C++ ve Python/JS ortamına aktarılacak yalınlıktadır.

Algoritma 1: Sabit 2 Atlamalı ESP-NOW Röle İletimi

Her sensör paketi node_id ve artan bir sıra numarası (seq_no) taşır. Röle düğümü daha önce gördüğü sıra numarasını tekrar iletmeyerek yayın fırtınasını (broadcast storm) önler; ttl (yaşam süresi) sayacı döngü güvenliği sağlar.

// Paket yapısı (toplam 16 bayt)
struct TelemetryPacket {
  uint8_t  node_id;      // Örn: 1 (Sensör)
  uint16_t seq_no;       // Her ölçümde +1 artar
  uint8_t  moisture_pct; // 0 - 100 kalibre nem
  uint8_t  hop_count;    // Başlangıçta 0
  uint8_t  ttl;          // Maksimum atlama = 3
};

// Düğüm 2 (Röle ESP32) alım geri çağrısı
void onDataRecv(TelemetryPacket pkt) {
  if (pkt.ttl == 0) return;
  if (pkt.seq_no <= lastSeenSeq[pkt.node_id]) {
    return; // Tekrarlı paket, yoksay
  }
  lastSeenSeq[pkt.node_id] = pkt.seq_no;
  pkt.hop_count += 1;
  pkt.ttl -= 1;
  esp_now_send(GATEWAY_MAC, &pkt, sizeof(pkt));
}

Algoritma 2: Histerezis, Yağmur Engeli ve Fail-Safe

Tek bir eşik değeri (örn. < %40) kullanılırsa pompa saniyeler içinde sürekli açılıp kapanır. Çift eşikli histerezis, yağış tahmini ve maksimum çalışma süresi sınırı sistemi kararlı ve güvenli kılar.

# Sabitler (masaüstü saksı güvenliği)
MAX_RUN_SEC  = 25   # Tek seferde maks. pompa süresi
COOLDOWN_MIN = 30   # İki sulama arası bekleme
RAIN_LIMIT   = 60   # 6 saatlik yağış olasılığı (%)

def decide_irrigation(zone, moisture, rain_prob, now):
  if zone.manual_override == "STOP":
    return {"pump": False, "reason": "MANUAL_STOP"}
  if zone.manual_override == "START":
    return {"pump": True, "sec": MAX_RUN_SEC}

  # Donanım güvenliği: sensör koptuysa veya bekleme sürüyorsa
  if moisture < 2 or (now - zone.last_run) < COOLDOWN_MIN:
    return {"pump": False, "reason": "SAFETY_LOCK"}

  # Yağmur tahmini yüksekse sulamayı ertele
  if moisture < zone.min_moisture and rain_prob >= RAIN_LIMIT:
    return {"pump": False, "reason": "RAIN_DELAY"}

  # Histerezis kuralı (Başlat: <%35, Durdur: >%55)
  if moisture < zone.min_moisture:
    return {"pump": True, "sec": MAX_RUN_SEC}
  if moisture >= zone.max_moisture:
    return {"pump": False, "reason": "TARGET_MET"}
  return {"pump": False, "reason": "HYSTERESIS_HOLD"}
